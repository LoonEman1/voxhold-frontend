# Voxhold 2.1.0

Совместимый релиз исправлений по аудиту 27 октября 2026.

- Один refresh на поколение авторизации, защита logout/login от старых ответов
  и 401; вкладки координируют ротацию через Web Locks и storage events.
- Каталог участников целиком восстанавливается после reconnect; HTTP/WS гонки
  не возвращают удалённых участников и не стирают роли, аватары и last-seen.
- Участники с доступом к каналу обновляются автоматически. Ручная кнопка
  «Обновить» удалена; повтор запроса после ошибки сохранён.
- Компактная карточка пустой голосовой комнаты по центру, отдельные SVG и
  короткие подписи для записи, списка записей и чата; состояния и focus сохранены.
- Backend 2.1.0 исправляет отложенные WebRTC offers/ICE, initial handshake,
  пустой server ICE, renditions, fan-out и ACL; добавляет локальную диагностику.

Порядок обновления: backend 2.1.0 → frontend 2.1.0. Новых миграций нет.
Также обновите Caddyfile из Voxhold-deploy для корректного trusted client IP.
Два браузерных клиента проверяют единственную ротацию и общий logout.
Без Web Locks межвкладочная блокировка недоступна; защита одной вкладки сохраняется.

Измерения и оставшиеся исследования:
[backend audit report](https://github.com/LoonEman1/voxhold-backend/blob/main/docs/audit-2.1.ru.md).
Нагрузочный smoke использует synthetic RTP; WAN/TURN/browser decoding не объявляются проверенными.

## Previous release

# Voxhold 2.0.0

Первый общий релиз фронтенда и бэкенда с одинаковым номером версии.

- Ответы на сообщения с переходом к оригиналу и обновлением цитаты после
  редактирования или удаления.
- Пересылка в доступные каналы с сохранением автора. Повтор после ошибки сети
  использует тот же ключ запроса и не создаёт дубликат.
- Реакции: быстрый выбор, раскрываемая палитра, поиск, категории, недавние эмодзи,
  счётчики и список участников при наведении.
- Исправлено первое открытие записей: рабочая область и звонок остаются на месте
  во время загрузки окна.
- Список участников с доступом к каналу обновляется по событиям без ручного
  обновления.
- Единый Gitflow: feature PR → dev → релизный PR в main. В обоих репозиториях
  защищены main и dev; образы, теги и GitHub Releases выпускаются автоматически.
- Go CI проверяет гонки и утечки горутин через профиль runtime Go 1.27.

Правила X.Y.Z: X — глобальные изменения, Y — новые совместимые функции,
Z — исправления текущей минорной версии. Подробности в docs/release-workflow.md.

Для обновления сначала установите backend 2.0.0 и миграцию 24, затем frontend
2.0.0. Перед миграцией сохраните проверенную резервную копию базы данных.
