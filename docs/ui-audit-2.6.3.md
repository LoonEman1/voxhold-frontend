# Подробное ревью UI и связанных сценариев 2.6.3

Изменения выполнены от актуального dev 2.6.2 в отдельных ветках frontend и
backend. Существующая локальная копия старого dev не использовалась как основа.
Описание поведения на английском и русском: [ui-refresh.md](ui-refresh.md).

Это ревью проверенных сценариев и исправленных дефектов, а не утверждение,
что в проекте больше не может быть ошибок. Подозрения сверялись с кодом,
существующими проверками и воспроизведениями. Например, внешний ключ уже удалял
участника звонка при выходе из беседы: исправлена задержка уведомления клиентов,
а не добавлено дублирующее удаление из базы.

## Звонки и трансляции

Звонок открывается отдельным окном с участниками, экраном собеседника и
предпросмотром своего экрана. Трансляция канала использует такое же управление
окном и открывается при запуске показа. Явный полноэкранный режим сохранён.
Окно можно перемещать и менять его размер мышью, касанием или стрелками;
Shift ускоряет действие, Home сбрасывает положение и размер. Положение
сохраняется, размеры ограничиваются доступным экраном и навигацией.

Перетаскивание пишет координаты непосредственно в DOM один раз за кадр;
React не перерисовывает медиакомпонент на каждом движении указателя.
Сессия звонка и video не заменяются при перемещении или изменении размера.
При смене размера экрана сохраняется предпочтительная геометрия окна.
Мобильные меню располагаются выше обычного окна звонка.

Горячие клавиши плавающей трансляции действуют, когда фокус находится в ней.
Окно не перехватывает F, Escape и Tab у остальных элементов приложения.
Полноэкранный режим восстанавливает фокус при выходе. Кнопки с визуально
скрытыми подписями сохраняют доступные имена. Светлая тема окна использует
цвета темы; видео и полноэкранный просмотр сохраняют тёмный фон.

Громкость трансляции регулируется до 200% как для зрителя, так и для
исходящего звука экрана. Для усиления зрительского звука Web Audio создаётся
только после запроса уровня выше 100%. Значение `video.volume` остаётся
в допустимом диапазоне 0–1. Последующие изменения используют тот же аудиограф.
Выключение и включение звука восстанавливает выбранный уровень. Закрываются
только собственные узлы и обработанная аудиодорожка; исходные дорожки не
останавливаются. Отдельная панель регулятора сохраняет место для процентов
и проверена в узком окне и обеих темах. Реальный браузерный тест измеряет
двукратное усиление амплитуды тихого тестового сигнала.

AV1 исправлен в backend: relay сравнивал строки FMTP буквально, хотя Firefox
и Chromium возвращают разный порядок параметров и уровни декодирования.
Теперь AV1 сравнивается по совместимому профилю, с Main (0) по умолчанию;
проверки других профилей, частоты и количества каналов сохранены. Также
учтены различия Opus и сохранена пара AV1/RTX. Настройки Firefox и смена
кодека для воспроизведённого дефекта не требуются.

Проверка на официальном Firefox 159.0 с отдельным временным профилем показала
315 декодированных AV1-кадров 1920×1080 без отброшенных кадров. Отправка
AV1 из Firefox в Chromium также проверена. Firefox 153
проверен отдельно. Браузеры обменивались реальным синтетическим видео через
производственный SFU Voxhold. Это проверка совместимости, а не обещание
фиксированного FPS на любом процессоре или аппаратном декодере.

## Асинхронные ошибки и безопасность данных

| Дефект | Исправление и проверка |
| --- | --- |
| Повторная отправка личного сообщения | Синхронная блокировка повторного запроса до обновления React-состояния |
| Старая загрузка уведомлений перезаписывает переключение | Поколения запросов и сериализация изменений |
| Очистка поиска оставляет вечную загрузку | Сброс загрузки и отмена запроса; тест с поздним ответом |
| Старая страница поиска смешивается с новым запросом | Отмена пагинации, игнорирование устаревшего ответа; регрессионный тест |
| Закрытая панель остаётся доступной с клавиатуры | `inert` и управление фокусом |
| Старая история теряется при фоновом обновлении | Независимая отмена загрузки истории, корректный курсор и привязка прокрутки; воспроизведение конкурентных ответов |
| Завершение старого запроса закрывает новый диалог | Привязка операции к открытию диалога, защита повторной отправки; тесты создания сервера, канала и сохранения профиля |
| Канал, созданный в предыдущем сервере, попадает в текущий | Проверка актуального сервера перед изменением списка каналов |
| Старый план очистки остаётся после неудачного пересчёта | План сбрасывается до запроса; фильтры заблокированы до ответа; тест отложенного ответа и ошибки |
| Ответ старого списка блокировок заменяет текущий | Проверка поколения запроса, сброс подтверждения при смене контекста, повторная загрузка |
| Конкурирующие открепления сбрасывают чужой статус | Сериализация действий; после ошибки список остаётся доступным для повторной попытки |
| Смена пароля частично сохраняется при ошибке отзыва сессий | Единая SQLite-транзакция, сравнение проверенного хеша, отзыв WebSocket после commit; тест принудительного rollback |
| Выход из беседы задерживает обновление состава звонка | Немедленное событие оставшимся участникам и вкладкам вышедшего пользователя; проверка ревизии и отсутствия утечки для неучастника |

## Оптимизация и пределы проверки

Новых зависимостей нет. Медиа, захват экрана и диалоги остаются ленивыми
модулями. Стартовый JavaScript после изменений: 599 994 байт, gzip 187 819,
Brotli 161 419; действующие лимиты 620 000 / 200 000 байт соблюдены.
Чанк WorkspacePage — 206 039 байт. Движения окон объединяются по кадрам,
настройки записываются с задержкой, быстрый ввод поиска объединяется в запрос.

Проверки включают TypeScript, ESLint, весь набор модульных тестов frontend,
сборку и бюджет JS, UI- и performance/media-наборы Playwright; backend —
`go test ./...`, `go vet ./...`, проверку утечек горутин и Linux race в CI.
Точные итоговые статусы находятся в PR.

Реальные серверы, аккаунты, трансляции и файлы пользователя не использовались
как тестовые данные. Исходный файл диагностики не добавлен в Git. Настройка
GPU, корпоративные политики браузера, внешняя сеть/TURN и нагрузка рабочего
инстанса требуют отдельной проверки в окружении развёртывания. Набор тестов
проверяет существующие сценарии записей, восстановления медиа, разрешений,
E2EE, вложений и состояния сессии; это не замена аудиту каждой возможной
конфигурации и тесту на проникновение.

Дополнительно: ручной видеобитрейт 0,5–16 Мбит/с с шагом 0,1, немедленным ограничением максимума, округлением и сохранением. Ввод 7.3 и ограничение 99.9 → 16 проверены также клавиатурными действиями в официальном Firefox 159. Итоговая матрица кодеков и ограничение отправки H.264 в чистом профиле описаны в backend docs/browser-codecs.md.
