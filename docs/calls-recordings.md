# Звонки, записи и аватарки

В голосовой комнате трансляция занимает основное место, ниже находятся плитки участников и панель звонка. LIVE у участника в списке каналов открывает его трансляцию; при необходимости клиент сначала подключается к голосу. У комнаты есть собственный текстовый чат с общей историей, поиском, закрепами и прочтением. Открыть чат можно кнопкой на панели звонка. Нажатие на видео разворачивает плеер; в полном экране остаются микрофон, звук, запись и выход. Интерфейс можно скрыть кнопкой полного экрана/F, вернуть движением мыши/Esc.

## Запись и размер

Круг на панели включает запись. Все участники видят красный индикатор у канала и имя записывающего в комнате. Повторное нажатие завершает запись и автоматически передаёт файл в загрузки браузера. Кнопка **«Записи» в верхней панели** открывает список с повторным скачиванием и состоянием копий, в том числе вне звонка. На нижней панели звонка тот же список открывается иконкой лотка с подсказкой «Список записей». Плеера записей в приложении нет.

Записываются текущая трансляция, её звук, собственный микрофон после обработки и полученные голоса собеседников. Если трансляции нет, записывается голосовой разговор с нейтральным фоном. Для экрана нужно уже публиковать/смотреть трансляцию; запись не подписывает пользователя на чужой экран автоматически. Отключённый микрофон даёт тишину. Входящие голоса записываются независимо от локальной громкости/выключения воспроизведения; это запись разговора, а не акустического выхода компьютера. Запись не останавливает и не меняет исходные дорожки.

Профиль записи: 1280×720, до 24 кадров/с, целевые 1,2 Мбит/с видео + 96 Кбит/с аудио. Это около **583 МБ за час** при полном целевом потоке; фактический размер зависит от содержимого и браузера. Настройки качества прямого эфира остаются прежними. Запись предназначена для компактного архива разговора; мелкий текст на экране может потерять читаемость при уменьшении до 720p. Кодек выбирается через MediaRecorder.isTypeSupported: VP8/Opus WebM, затем H.264/AAC MP4 и общие форматы. VP9 программно не навязывается.

## Локальная и серверная копии

- Медиа каждые две секунды сохраняется в IndexedDB; файл не накапливается целиком в массиве байтов JavaScript. Готовый Blob собирается из этих частей для скачивания. Конкретный браузер может всё равно потреблять дополнительную память при сборке/скачивании больших Blob.
- Файлы **до 2 ГБ включительно** (2 147 483 648 байт) ставятся в очередь на сервер. Пока пользователь находится в голосовом звонке, загрузка приостановлена. После выхода идёт последовательная передача частями по 256 КиБ с продолжением по фактическому смещению.
- Все серверные копии инстанса вместе занимают не больше лимита: **6 ГБ** по умолчанию (`RECORDING_STORAGE_QUOTA_BYTES`). Владелец меняет его в «Настройки сервера → Хранилище записей» от 1 до 1024 ГБ; там же видно, сколько занято. Уменьшение лимита касается новых загрузок, уже сохранённые копии удаляются по истечении срока.
- На сервере копия хранится **24 часа** и доступна текущим участникам сервера. Для скачивания запрашивается короткая подписанная ссылка, затем браузер скачивает файл потоково, без fetch/Blob на весь серверный файл.
- Файлы больше порога остаются только в этом браузере. Локальные копии привязаны к аккаунту и адресу инстанса и остаются до явного удаления. «Удалить локальную» не удаляет серверную копию. Очистка данных сайта удаляет локальные записи.
- При нехватке места/ошибке серверная копия не заменяет локальный файл. В списке есть повтор загрузки. Если локальный диск заполнен, запись останавливается и скачивает доступную часть; несохранённый хвост доступен до закрытия вкладки. Прерванный контейнер после сбоя браузера может потребовать внешнего восстановления.
- При выходе/смене голосового канала запись завершается. Ограничение одной записи — 24 часа. Не закрывайте вкладку до скачивания и, если нужна общая копия, до завершения её загрузки. Автоматические загрузки могут блокироваться настройкой браузера; ручная кнопка скачивания остаётся доступной.

## Накладная работа

В Chromium уменьшение/перерисовка кадров выполняется в Worker с OffscreenCanvas и отдельной сгенерированной дорожкой. Используется клон входящей видеодорожки, буфер входа ограничен одним кадром, запись ограничена 24 FPS и одним незавершённым выводом. При смене источника выходная дорожка MediaRecorder остаётся той же. Для старых API есть canvas fallback на основном потоке; его производительность и работа фоновых вкладок зависят от браузера.

Один дополнительный AudioContext смешивает дорожки в одну с компрессором против перегрузки. Подписки на изменения аудио/видео обновляют граф только при смене дорожек. Переключение микрофона не пересоздаёт видеоплеер. Энкодер записи всё равно требует ресурсов; аппаратное ускорение конкретной комбинации кодека/устройства не гарантируется.

Для смены аватара откройте свой профиль нажатием на аватар внизу слева. Наведение на фото в профиле показывает камеру; нажатие открывает выбор изображения и удаление текущего аватара. После выбора JPEG/PNG/WebP/GIF до 5 МБ и 16 мегапикселей можно двигать фото мышью/пальцем, менять масштаб и положение ползунками. Загрузка начинается только после «Сохранить аватар»; отмена не меняет текущий аватар.

Сервер получает исходный файл и координаты выбранной области, учитывает JPEG EXIF-поворот и сохраняет только круглый PNG 256×256. Пиксели вне круга и исходник удаляются; прозрачность сохраняется. Старые JPEG-аватары поддерживаются. Список участников и avatar.updated передают версию (`avatar_version`, ETag) аватара. Клиент запрашивает только видимые аватары с известной версией: для пользователей без аватара остаются инициалы без запроса к серверу. Одновременные запросы объединяются, кеш неиспользуемых Blob URL ограничен. URL содержит версию (`?v=`), поэтому HTTP-кеш хранит картинку без перепроверки, а смена аватара просто меняет адрес. Голосовой чат загружается и подписывается на сообщения, когда открыт.

Предыдущие оптимизации AudioWorklet, видеопотока, виртуализации сообщений, getStats и диагностики описаны в [client-performance.md](client-performance.md). Их следует оценивать вместе с дополнительной нагрузкой записи.

## Проверки и ограничения

`npm run test:e2e:ui` проверяет геометрию аватарок и индикатора записи, обе темы, список записей на узком экране, меню камеры, перемещение/масштабирование, загрузку оригинала с координатами и удаление. Можно использовать установленный браузер, задав `VOXHOLD_E2E_BROWSER_CHANNEL=msedge` или `chrome`.

`npm run test:e2e:performance` проверяет реальные AudioWorklet/Worker/MediaRecorder в Chromium, ограничение DOM длинного чата, автоматическое и повторное скачивание, сохранение в IndexedDB, размер/разрешение файла, сохранение исходных live-дорожек, смену источника и паузу серверной загрузки до выхода из звонка. Сценарий интерфейса использует тестовый API; права, лимиты, файлы и скачивание настоящего API покрыты backend-тестами с реальными миграциями.

Отдельные реальные звонки в Яндекс Браузере, Firefox и Safari и нагрузочная сессия с десятью участниками на целевом сервере ещё не выполнены. `test:e2e:stream` требует настроенного тестового инстанса и двух учётных записей; он проверяет SFU/TURN-восстановление. Наличие capability fallback не является подтверждением проверки каждого браузера.
